# NexusDesk v1.0 — Read-only Render Deployment

This deployment is for a **synthetic portfolio demonstration only**. It is
intentionally separate from the authenticated local helpdesk and must not
receive actual staff accounts, support records or assets.

## Current hosted demonstration

The public synthetic demonstration is available at **https://nexusdesk-demo.onrender.com/demo/**. GitHub-hosted HTTP verification [passed on 29 October 2026](https://github.com/eddy235/NexusDesk/actions/runs/40844351137). The verification checks the deployed v1.0 page, fictional filters, CSS, expected security headers, blocked private routes and rejected POST requests; it does **not** certify the host or app against all vulnerabilities.

## Create a Render Blueprint

1. In Render, connect your GitHub account if necessary, then choose **New → Blueprint**.
2. Select `eddy235/NexusDesk` on branch `main` and use its `render.yaml`.
3. Review the `nexusdesk-demo` web service before applying. The Blueprint specifies:
   - `NEXUSDESK_DEMO_MODE=true`
   - `DJANGO_DEBUG=false`
   - `DJANGO_SECRET_KEY` generated by Render
   - `DJANGO_SECURE_SSL_REDIRECT=true`, `DJANGO_ENABLE_HSTS=true`
   - `healthCheckPath: /health/`
4. Confirm a successful build and capture the service's actual `https://` URL.
5. **Do not** add a real database or run Django migrations on the public demo.
6. **Do not** create an admin account or enable internal workflows on the public service.

## Validate the live service

In a terminal with Python installed, use the real URL that Render gives you:

```bash
python scripts/verify_demo_http.py https://nexusdesk-demo.onrender.com
```

The script confirms demo mode, the synthetic dashboard, static CSS, security
headers, disabled private routes and rejected write requests. It sends no
real ticket data and makes no changes.

Also check by hand on desktop and mobile:
- Ticket search and status/priority filters work with fictional records.
- Asset lifecycle filters work.
- No links offer admin login or real ticket creation.
- The banner and footer plainly identify the data as fictional.

If a verification fails, do not share the link as a finished project. Review
Render build/runtime logs and confirm environment variables. Keep the previous
working deployment in place until the issue is corrected.

## Architecture and limitations

`render.yaml` deploys Gunicorn serving Django with WhiteNoise static files.
The demo has no persistent database requirement and no public write endpoints.
Private local deployments may optionally use PostgreSQL through `DATABASE_URL`,
but those are separate environments and are **not** covered by the public-demo
security assertions.

The Render free plan may become inactive with no traffic. These checks cover
specific workflows and headers; they do not constitute a penetration test,
independent security audit, or availability guarantee.
